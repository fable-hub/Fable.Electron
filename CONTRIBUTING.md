# Welcome

Thank you for showing interest in contributing to Fable.Electron.

# How to Contribute

## Contribution

* Troubleshoot problems in existing code or issues
* Submit Bug/Feature issues
* Submit documentation issues for insufficient documents, or suggestions
* Join discussions on issues/PRs

## Collaborators

Collaborators would benefit from [reviewing the `Dev` section](https://fable-hub.github.io/fable-electron/docs/dev/introduction) of the docs.

* Immediate communication preferred through Discord.
* Ensure that you make pulls to `develop` before `main`. This is not rigid; there are circumstances where a pull might be made to `main` rather than `develop`.

Automatically generated Pull Requests can have their reviewer, label, project, and assignee fields filled automatically.

Edit `ci/pull_request.json` as required.

## Making a PR

Please check that no duplicate PR has been raised. We would greatly appreciate an issue being created with the feature/issue you plan to tackle.

# Tools

## Build System

The build system should give all contributors a single tool to use to run various operations within the repository.

## Formatting/Fantomas

* 4 Space indentation
* Please use Fantomas before submitting code for pull requests. You can run `dotnet run -- format` from the root of the repository.

# Standards

## Commit Messages

We follow the standards set by [ConventionalCommits](https://www.conventionalcommits.org/en/v1.0.0/).

This is critical for our versioning system.
Make liberal use of squashes if required when making or merging a PR.
